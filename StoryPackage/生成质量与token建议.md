# 生成质量、token与缓存

简短稳定的约束可减少错误、反复解释和重写，但不能保证总token下降。每轮仍要提交规则；规则过长、增加很多示例也会提高输入。衡量应使用“每个有效剧情进展的总输入、输出、推理和返工次数”，而不是单纯每次回复字数。

已加入表层规则：围绕玩家意图推进，只写相关观察、回应或已裁定后果；避免重复景物和自我提醒；没有新证据保留未知，不为凑情节编造线索。规则随系统前缀固定，不随时间或心情变化。尚未用独立人工标注样本证明错误率下降。

缓存布局已修正：旧实现把JSON按字母排序，时间和状态排在历史前，导致很早失配。新实现保留字段语义和可见性，按场景资料、上一场景摘录、已发生历史、按需检索、本轮状态及输入排序；每个字段内部仍确定性排序。不会为缓存而保留过期检索，也不会塞入未公开设定。

优先改进方向：

1. 场景结束时形成结构化摘要：已发生事件、获得物品、已知人物关系、未解决问题、来源与不确定性。当前1600字符末尾截取可能漏掉早期线索；摘要应在场景结束或需要压缩时生成，不每轮重复生成。摘要生成本身也有token成本。
2. 表层叙事与里层复杂创作可分别试验推理设置或模型，再比较剧情一致性。实测V4 Pro的16轮输出中推理占88%；不应单靠压缩正文解决。是否支持关闭/调低推理，以实际接口能力为准，尚未自动变更。
3. 知识点按需取，避免让最近对话和知识摘要重复携带同一段原文。删减前要保留证据、否定与传闻限定。
4. 固定少量叙事规则，大量风格语料按场景/人物选择；不要每轮重复提交整套范文。当前“通用语料”主要是规则文本，不等同于已训练的模型。

限制：最近6轮的窗口滑动会改变历史首项；新场景内容变化也会使缓存重新建立。增加更多历史有时提升命中率却增加总输入，不能为了一个百分比牺牲总体成本。缓存命中通常改变输入计价与计算量，不降低输出token；真实收费应按供应商当前模型价格计算。
