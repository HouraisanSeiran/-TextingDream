# 按需知识点 token 对照

使用 deepseek-ai/DeepSeek-V3 官方 tokenizer.json 本地分词；不执行远程代码，不发送付费模型请求。当前 deepseek-chat 的线上分词或聊天模板可能不同，因此是 V3 分词参照，不是线上账单。计数对象是序列化 system 正文和 user 上下文正文，不含聊天协议特殊 token。

下载来源：https://cdn.deepseek.com/api-docs/deepseek_v3_tokenizer.zip

分词文件 SHA256：c64606bf6af0f5b7505e4b9c0bbd19e2c0dcabc8a408abdeda9f36fb9e9db8b4

故事包共 56 点，其中公开候选 43 点。比较同一扩充版总概、同一问题和同一动态字段，只有知识点选择变化；各样本最多6点、3600字符。

四组同权样本合计减少 21,410 / 25,036 输入 token，即 85.5%。

旧版表层本来只发送很短的公开设定，不能声称这次比旧版同样降低了上述比例；新增细节的按需提示可能比旧版更长。公平节省比例针对“同等扩充资料全部注入”的方案。实际轮次加入相同历史 H 后，节省比例为 (全量−按需)/(全量+H)，历史越长整体比例越低。

本地关键词摘录额外模型调用为0、额外生成摘要 token为0。对话输出 token 未在此假定减少；上下文缓存命中、价格和真实请求使用量需读取模型输入输出控制台 usage。固定总概有助保持前缀稳定，但这里不承诺缓存命中率，也不把输入节省直接称作费用节省。关键词检索可能漏召回，应在里层查看实际 knowledge 字段并补关键词或依赖。

复现：在工程目录运行 `D:\anaconda\python.exe -X utf8 tools\measure_knowledge_tokens.py`。原始样本 ID 和计数见同目录 JSON。
