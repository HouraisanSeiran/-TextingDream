# 社会制度元素候选目录（society 组）

对应 `society.json`。状态：**候选资料**，不是数据库记录，也没有被任何故事包采纳为正典。本文件只提供扫读视图与说明，完整字段（requires / excludes / entry_modes / introduction_limits / evidence_note）以 JSON 为准。

适用题材：`historical`（历史／架空历史）、`modern`（现代都市／现实社会）。共 **53 项**元素：41 项可用于历史向、28 项可用于现代向，其中 16 项两个题材共用。

> **本版已扩充详情**：53 项全部具备 `details` 七节（definition / mechanism / conditions / exceptions / story_consequences / adaptation_limits / evidence_and_uncertainty），平均约 880 字/项；`detail_status` 统一为 `needs_detail`（已写七节但未经主审审阅，不得当作 reviewed_detail 引用）。下表 `summary` 仅作扫读，**完整机制、例外与适用条件以 JSON 的 details 为准**。
>
> **字段语义（重要）**：旧 `requires` 应读作「常见条件」而非必要条件；旧 `excludes` 应读作「常见失效或不适用情形」而非普遍排除——它们说的是该元素通常被压缩或失效的前提，不是宣布某种社会「不存在」。与 `details.exceptions` 冲突时以后者为准。
>
> **开局预绑定**：所有元素均为开局前选定并固定版本的候选，**不在故事中途从库中新增**。`entry_modes` 只描述已绑定元素在世界内的显现方式（已存在／之后被发现／玩家在已许可边界内提出实现），不是三个允许运行中跨库导入的入口。

## 一、这个组在收集什么

用户要求「不写代码不建库」，只要通用母题；同时明确**现代不等于科技道具**。所以本组覆盖的是"制度如何形成、如何运转、如何卡住人"：

- 政体与决策：宫廷、等级会议、科层官僚、家产制官吏、市政会、等级会议
- 身份与阶层：爵位位次、骑士阶层、四民分业、贱籍、士绅、户籍
- 土地与税赋：封土继承、庄园劳役、地籍田赋、徭役、什一税、关市税、包税
- 组织与信仰：行会、商团、宗族、修会、堂区、异端审判、大学、私塾、慈善
- 法律与武力：习惯法与法典、审级上诉、领主司法、民兵、军户、佣兵、警察
- 城市与自治：特许状、市政会、业主自治、居委会式基层
- 商贸与金融：铸币成色、票据汇兑、票号钱庄、消费信贷、有限责任、董事会
- 现代生活面：劳动合同、工会、劳务派遣、社保、义务教育、就医医保、大众传媒、行政审批、家庭结构

**刻意不做的**：不把赛博义体、星际装置、异能力量塞进现代条目当作"现代元素"；也不把某一地域制度（如西欧采邑、中国科举）写成全世界通例，历史向条目均标注地域与时期。

## 三、跨题材共用点与跨组共享

### 3.1 历史与现代真正共用的 16 项（不是把两套文本拼在一起）

这些元素在两个题材里**机制同构、表现不同**，因此只记一条、用 variants 区分形态，避免重复凑数：

- 选拔与文书：`bureaucratic_merit`（科举↔公务员考录）、`administrative_service`（关防核验↔行政许可）
- 记录与资格：`household_register`（编户↔常住与流动人口登记）、`customary_law`（习惯↔成文／判例）、`court_hierarchy`（越诉↔二审再审）
- 经济中介：`market_duty`（关市税↔摊位费与许可）、`tax_farm`（包税人↔政府购买服务）、`bill_of_exchange`（飞钱票号↔信用证与电子支付）、`deposit_house`（钱庄↔受监管银行）、`consumer_credit` 与 `deposit_house` 的信用逻辑互为对照
- 组织与互助：`lineage_clan`（祠堂宗族↔家族企业）、`charitable_relief`（义仓善堂↔社会救助）、`city_council`（行会市政会↔市议会）
- 知识与传播：`private_academy`（私塾↔补习机构）、`medieval_university`（特许讲学↔现代大学）、`mass_media`（报刊↔平台舆情）
- 生活单位：`nuclear_family`（主干／联合家庭↔核心／留守家庭）

## 四、组合与限制（写故事时必须守住的三条）

1. **主角一句话拿不到组织认可与法权。** 每条的 `introduction_limits` 都写了具体门槛：行会要学徒年限与考核、公司要登记与资本、工会要会员名册与推举、宗族要谱系核验与义务履行、士绅要功名财富加数代公共服务。写作时若想跳过，须显式写出交换条件（垫付、担保、联姻、政治支持）与代价。
2. **制度不会一次宣布即成。** 世袭化、役的货币化、教育普及、社保扩面、特许状取得，都是数十年的既成事实＋一次事后确认；`entry_modes` 里给 `discovery` 的只有两项（宫廷、票据），其余多为 `existing` 或 `player_proposal`。
3. **地域与时期不能混用。** 采邑、庄园、什一税限于西欧特定时期（且南法、德意志、意大利差异很大）；科举、宗族、保甲限于中国；警察职责清单、居委会、劳动合同、社保缴费来自中国当代法条，不能直接当作任何国家的通例。同一制度名在不同地域差别极大——农奴制在西欧约10世纪形成、俄国1649年确立至1861年废除、旧西藏延续到1959年，就是最清楚的例子。

### evidence_note 的写法约定

每条 `evidence_note` 都分成两半：**来源支持了什么**（带 src 编号，可直接核对）与**哪部分是本项目归纳**。尤其注意三类必须标明归属的内容：

1. 引自《管子》的四民分业、土地折算、力役定额——是**先秦文献的制度主张**，不等于当时已全面实施；
2. 中世纪欧洲诸条目——限定西欧，且注明南法、德意志、意大利差异，不外推；
3. 中国当代法条类条目（劳动合同、社保、警察、义务教育、居委会）——是**中国制度**，地域性极强，不能当作现代社会的通例。

凡在来源中找不到直接支撑的机制（如胥吏层的具体形态、包税合约形式、征信评分），一律写成"本项目归纳"，并说明须另核实，**不伪造引文、不假装有出处**。

### details 七节的读写约定

每项的 `details` 统一七节，顺序与用途如下：

| 节 | 写什么 | 不应写什么 |
|---|---|---|
| definition | 这个制度的本体是什么（把它与相邻概念区分开的那一句） | 重复 summary 的改写句 |
| mechanism | 权力／义务／资源／资格／执行／退出六要素，以及争议通常卡在哪几点 | 人物情节或具体作品的例子 |
| conditions | 常见条件（不是必要条件），并说明缺哪条会导致什么状态 | “必须”“一律”式的刚性前提 |
| exceptions | 区域与时期的差异、并行形态、反例，以及“看不到机构不等于没有机制” | 把某一地做法写成全人类通例 |
| story_consequences | 制度运转产生的具体摩擦：谁受损、信息在哪里断、程序滞后多久 | 抽象主题词（如“引发思考”） |
| adaptation_limits | 预绑定时必须写明什么；主角要做什么需哪些具体条件；中途可改与不可改的边界 | 将“一句话完成制度变革”合理化 |
| evidence_and_uncertainty | 分三层：已证事实（带 src）、争议/存疑、设计推演 | 把设计推演写成事实，或把书目介绍当程序描述 |

特别注意二类容易越界的写法：

1. **历史制度不统一现代化**。采邑、行会、什一税、城市自治都是特定地域与时期的产物，不能包装成“古代普遍如此”；现代也不能倒推为历史制度的“升级版”。
2. **社会描述不等于规范性理想**。写法条时要区分“条文怎么写”与“实际怎么执行”，并标地区与版本日期（例如劳动合同、社保、警察职责均来自中国现行法，不得当作任何国家的通例，也不得写成永恒精确的法条）。
