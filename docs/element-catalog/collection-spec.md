## 交付形式

每组提交同名 `.json` 和 `.md`，位于本目录。JSON 是候选交换格式，不保证已经符合未来元素数据库的正式 schema。

JSON 顶层：`schema_version: 1`、`status: "candidate"`、`group`、`genres`、`sources`、`elements`。

来源：`id`（组前缀）、`title`、`url`、`access`（read/search_only/unavailable）、`supports`（该来源可支持的范围）、`rights_note`。实际读过正文才能写 read；不编造检索结果或引文。

元素字段：
- `id`：组前缀稳定小写英文 ID。
- `name`：中文通用名。
- `genres`：上述题材 ID 列表。
- `category`：生命物种/力量技术/物品资源/地点探索/社会制度/组织信仰/经济生产/冲突事件，使用 snake_case ID（life/power/item/place/institution/organization/economy/conflict）。
- `summary`：1—2句，说明它是什么及为何影响剧情，不复述专属作品情节。
- `variants`：2—4项常见变体；不称所有作品都遵守。
- `story_roles`：1—3项可参与剧情的功能。
- `requires`：自然语言条件列表，不把尚未实现的外部 ID 当已存在依赖。
- `excludes`：冲突或限制条件列表。
- `background`：技术/能源/社会/超自然条件的简短说明，不只给一个线性科技等级。
- `entry_modes`：existing/discovery/player_proposal，按合理性选。
- `introduction_limits`：从概念、局部原型到普及的限制、成本和传播范围。
- `source_ids`：引用本文件 sources 内的 ID。
- `evidence_note`：区分来源支持与设计归纳；涉及历史和民俗必须限定地域/时期，不把信仰叙述当经验证实事实。

每组约40—55个关键元素，组内每题材至少20项可适用；避免凑数。覆盖制度、组织/宗教和经济，不能只堆能力装备。200—350中文字符只作为扫读摘要的参考，取消对完整条目的篇幅限制；不能为了压缩删掉机制、例外或适用条件。已有四组是首批候选摘要，不能称为完整定义。Markdown便于扫读，JSON保存结构化字段；复杂条目另增 `details`（定义、机制、前提、例外、后果、跨题材边界、来源与不确定性分节），与 `detail_status`（summary_only/needs_detail/reviewed_detail）。长度本身不代表完整，未经详细审查不能标reviewed_detail；来源原文链接不替代本地完整归纳。

## 搜集和审查规则

- 搜集普遍、重要的母题；没有作品专有名称也能理解和复用。通用母题与具体作品许可分开，优先转述/归纳，不大段复制。
- 每组实际搜索并阅读至少4个不同页面，尽量覆盖两题材及制度/社会；使用专门可信来源或可靠参考。搜索摘要不是全文依据，失败要如实记录。
- `source_ids`用于溯源，不假装每一项细分玩法都是来源原话；`evidence_note`标出本项目设计归纳。
- 不把现代小说常见结构称为历史事实，不把东方玄幻/修真等同于真实道教，不把西幻宗教等同于现实宗教，不把黑暗奇幻统一认定为中世纪。
- 默认与背景条件相近者优先；火药、蒸汽原型、新航路可以经探索/发明/玩家提案出现，但须有材料、知识、工艺、能源、成本和制度条件。原型不等于量产，局部发现不等于全球普及。
- 玩家可主动提出外题材元素，但跨度大的内容必须更严格审核；不得用魔法万能兜底抹掉所有条件。
- 不改源码、正式世界包、数据库或其他组文件；不下载大批正文、不安装依赖、不训练模型。实现与入库须后续另行验收。

## 最新决策：开局绑定，不在故事中途选库

开局前由作者/玩家选择元素与允许的发展方向，展开依赖、兼容检查并固定版本和必要详细内容，形成世界元素清单。开局后不得从全局元素库检索并新增未绑定类型。已有 `entry_modes` 只描述预绑定元素在世界内的显现方式：existing=已存在，discovery=之后被发现，player_proposal=玩家在已许可边界内提出实现/使用。不是三个允许运行时跨库导入的入口。

预绑定不要求开局公开全部内容：已存在但未知的对象、尚未实现的技术、未掌握能力可列为潜在元素。后续从潜在到原型、制造、解锁、发现只更新本地旅程状态。新大陆可早已客观存在而角色尚不知情；蒸汽技术可被预绑定为允许研发但尚无成品。主角中途提出未绑定元素时，不静默补库；提示超出本局范围，由作者另建版本及新旅程/显式分支后采用。

这里禁止的是运行中重新挑选外部元素，不禁止读取开局固定的本地状态、完整资料与对话证据；这些仍是长篇一致性所必需的上下文来源。此为待实现设计，不声称当前引擎已实现锁定清单。

## 现实基础库（用户新增，候选采集）

独立分区 `reality-physical` / `reality-human`，题材标签用 `real_world`；不重复创建已有社会制度变体，以引用/关联为主。只收能影响人物行动、世界构建或事件因果的现实知识：自然与地理、物理化学/能源材料、农业生态/公共卫生、生产交通通信、历史制度、宗教与信仰实践、家庭组织/法律经济等。不是完整百科，也不是自动将现实一切装进每局。

区分可检验现实机制、带地域时期的历史事实、信仰/传统的记述、争议与本项目创作适配；不把神迹、修行或灵异效力当科学事实。现实基础可作为默认候选，但仍须开局选择适用版本/条件；架空世界如覆盖现实规律，应显式声明覆盖范围，不悄悄混用。

现实条目保留统一14字段，增加 `knowledge_kind`（empirical/historical/belief_description/mixed）、`details` 分节与 `detail_status`，不设完整内容字数上限。事实精确度和操作细节以故事用途为限，避免危险实验、医疗处方或现实伤害操作教程。来源优先机构/博物馆/教育与可靠参考，未核实处如实标注。
