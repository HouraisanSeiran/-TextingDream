# 跨题材叙事元素库设计方向

更新：2026-10-25。状态：用户已确认需求，待实现。待办见 [叙事工作台 TODO](narrative-todo.md)。

## 定位

元素库是独立于故事包的本地版本化素材与规则目录，不是新的语言模型。一个元素既能提供设定，也能通过受校验的参数、关系、条件和规则参与世界构建。王国、公会、种族、职业、法术、地下城和战利品规则等均可成为元素；西幻、东方玄幻、异常收容/灵异、蒸汽朋克与现代科技是来源标签，而非互斥数据库。

## 三层边界

1. **元素库模板**：跨世界可复用的设定或规则，保存稳定 ID、类型、版本、参数、依赖、冲突、来源与许可。
2. **故事包采纳版本**：作者选入、适配并审核后成为该世界的正典，固定来源版本并保存可导出的快照。库中新版不自动覆盖它。
3. **旅程实例**：某个具体国家、公会、人物职业、物品、异常事件或地下城的当前状态，与旅程绑定、持久化和回滚。模板不保存所有旅程共享的可变库存或阵营关系。

本地资料库可单独使用 SQLite 文件；物理独库并非必要，逻辑独立与版本边界才是关键。实施前确定存储方案，不能因跨库引用让旧旅程依赖一份可被删除或改写的外部素材。

## 建议元数据

- `id` / `type` / `revision` / `schema_version`：稳定身份、类别和结构版本。
- `name` / `aliases` / `genres` / `tags`：显示与检索。
- `description` / `parameters` / `rule_refs`：设定文本、严格结构化数据、受支持的本地规则引用；不执行任意脚本或 eval。
- `requires` / `conflicts` / `world_constraints`：依赖、互斥、时代/力量/技术条件与数值量程。
- `relations`：组织隶属、职业授予、资源需求等类型化关系；可复用模板关系与实例实际关系分开。
- `visibility` / `public_fields`：作者秘密与公开设定分离；实际角色知情在旅程层判定。
- `provenance` / `license` / `adaptation_notes`：出处、许可和改编记录。

具体字段、类别 schema 与查询协议为待设计内容，不表示已有 API。

## 组合而非直接混用

故事包声明允许的元素集合与世界规则。一个西幻公会和一个蒸汽动力装置可以共存，但必须明确能源、技术、社会背景与能力边界；不能因带相同“能量”标签就自动把灵力、魔力、电力与异常力量换算为同一资源。

模板选入需经历：检索 → 依赖展开 → 世界兼容性检查 → 作者适配 → 审核 → 固定版本。模型可以建议组合，但不能把候选设定直接升为权威事实。

## 现有能力与缺口

现有故事包版本、知识点、投影及本地奖励模块可以作为接入基础；`mechanics.rewards` 已支持一部分物品与能力规则。本需求新增的是跨故事包可复用的类型化元素目录、版本化采纳与组合校验，不应把现有知识点检索或作者生成候选误称为完整元素库。

外部地形生成器后续接入时，资源与势力生成应读取世界允许的元素版本，再产出具体世界实例。当前只记 TODO，等待用户提供生成器后再核对实现条件。

## 题材采集与跨题材引入规则（新增用户决策）

状态：设计要求，尚未实现。先列常见题材供用户选择，选定后再派 VMH DeepSeek 按题材收集，不提前大规模抓取所有题材。

### 收集范围

收集普遍、重要、能影响剧情与规则的元素，不堆砌某部作品专属人名或名词。例如东方玄幻的灵根、境界、宗门，西幻的龙、魔法、王国、公会。每个题材同时覆盖物种/生命、力量与能力、物品资源、地点与探索、社会制度、组织宗教、经济生产、常见冲突，不仅收集装备与技能。元素记录常见变体和适用条件，不能把某一小说的惯例当成全题材硬规则。

选定后按题材派收集子任务，主代理统一去重、对照来源和审查：先产出可阅读的候选元素目录与依赖关系，审核后再作为元素数据库内容；搜到资料不等于已写入世界正典。来源需标明普遍母题、历史参考或特定作品及许可。

### 默认筛选

故事包声明背景条件，至少区分技术能力、能源与材料、生产与加工、交通通信、社会制度、超自然力量及其代价。题材标签只作检索入口，不是单一兼容判断。例如常规西幻可采用中世纪至文艺复兴风格，但并非所有西幻都处于同一时代。

默认优先选择与当前背景水平相近或有明确铺垫的元素；不得因为元素库中存在某项技术或能力就随机投放。黑火药与早期火器可符合部分中世纪/文艺复兴背景；实用蒸汽动力通常需要作为技术突破核对精密加工、材料、燃料、安全与组织条件，不能视为所有中世纪世界天然具备。

### 三种进入路径与发展状态

- 开局已有：经作者选择成为世界既有设定，记录普及范围。
- 冒险发现：例如小镇发明家的蒸汽原型、遗迹中的未知装置或新航路；先记录局部存在、证据与知情者，不自动改写全世界历史。
- 玩家主动引入：主角可以提出其他题材的元素，形成结构化引入提案；是否具备知识、材料、能源、工艺、学习/实验条件、成本和风险由本地规则及作者设定约束。允许局部、失败或替代结果，不能输入一句话就获得成品或能力。

区分概念/传闻、设计、原型、局部可用、可复制、规模化、普及等状态；发现原型不等于已量产，知道蒸汽机原理不等于掌握制造工艺。新大陆类元素还须区分客观存在与某个群体首次知晓，不默认那片土地无人居住，也不默认整个世界都知道它。

### 跨度与审批

可配置为背景相近优先、有条件突破、需作者批准、当前世界禁止。例：中世纪风格世界的蒸汽原型可作为有条件突破；常规赛博义体、全球数字网络或星际装置与它跨度较大，应严格审查或只作为无法复制的遗物候选。魔法替代工艺须有已设定的能力、代价与限制，不能成为无限跳过前置条件的借口。

记录引入来源、玩家/发现者、事件、条件、资源消耗、实验结果、传播范围和对势力/经济/宗教的后果；保持版本与旅程隔离。故事内的新发现先改变本旅程，升级成通用素材或故事包正典须另走作者采纳流程，不直接重写所有旧旅程。

## 后续用户修订：完整资料、开局锁定与现实基础库（以本节为准）

- 取消完整元素条目的200—350中文字符限制。短摘要只用于界面浏览，完整定义、机制、前提、例外、后果、来源与不确定性分节保存在本地；现有首批目录属于候选摘要，详细化需按实际缺口补充，不能凭长度判定完整。
- 元素调用与选取在开局前完成，固定可用元素、依赖闭包、版本和详细资料。故事中途不从全局库新增元素类型。旧“冒险发现/玩家引入”只在开局允许的潜在集合内发生；发现、研发或解锁不等于重新选库。
- 开局可允许某种外题材发展但暂时不存在成品。中途超出集合的提案不自动引入；需作者明确创建新故事包版本、新旅程或显式分支。读取已经绑定的本地资料、权威状态及历史证据不属于重新选库，仍需支持。
- 增加现实基础库候选分区：科学自然、材料能源、地理生态、农业生产、交通通信、公共卫生、历史制度、宗教信仰、家庭组织与经济法律等与故事有关的现实元素。与题材库分层关联，不逐局无条件全部装载。
- 科学可验证机制、历史地域事实、信仰观念、争议和创作改编分别标注；信仰记述不证明超自然效力，架空改写需显式声明。完整百科不是目标，危险实操/诊疗处方不是收集内容。

## 真实基础资料与详情状态说明

- 现实基础库候选分为 `reality-physical` 与 `reality-human`，用于故事因果、人物行动和社会背景，不是完整百科，也不自动进入每个世界。
- 当前现实库与四组题材元素都属于候选资料。`details` 已补齐只表示采集代理写出了详细候选说明，不代表内容已由主代理逐条事实核验。
- `detail_status=needs_detail` 表示候选仍需详细化/证据审查；只有主代理逐条核对结构、来源、关键事实、例外和跨字段矛盾后，才可升格 `reviewed_detail`。抽查不能代替全量事实核实。
- 现实资料中的 `empirical`、`historical`、`belief_description`、`mixed` 要分开阅读：信仰、民俗和类型设定的存在不证明其超自然效力；历史制度和现代法律有地域/时期边界；设计归纳必须明确写成设计归纳。
