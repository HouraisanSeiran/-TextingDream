# 城镇生成 V1 · 使用说明

本文只写**已经实现并测过**的能力与**明确的边界**。设计讨论见主目录 `TOWN_GENERATION_V1_PLAN.md`，工程总览见 `工程说明.md`。

## 一句话

生成一座可游玩、可审阅、可版本化的城镇：**本地固定规则裁定结构与数值，语言模型一个字都没参与**。V1 不是"训练好的本地 AI"，也不是外部地形生成器的接入——后者仍未实现。

## 入口

- 侧边栏「**城镇创作**」，或作者接口 `/api/inner/towns*`（沿用既有 token）。
- 玩家侧只有 `GET /api/sessions/{id}/towns`（见下文「信息边界」）。

## 四阶段

| 阶段 | 内容 | 什么时候失效 |
|---|---|---|
| 1. 聚落骨架 `skeleton` | 类型/等级、名称候选、建立理由与时期、示意坐标、选址理由、水源方案、道路（含年封闭天数）、承载上限与依据 | 编辑它本身不会失效，但会清除后面三阶段 |
| 2. 社会经济 `socioeconomy` | 人口总数与组群（占比之和固定 1000‰）、治理形式与合法性来源、势力（公开目标/权力来源/资源/义务/限制/关系/证据/隐藏目标）、生产链、进出口、劳力分配、口粮与需求、矛盾、现实或艺术档的证据说明 | 编辑骨架后 |
| 3. 建筑与特殊地点 `built` | 街区（材料/屋面/排水/层数/可达）、代表性设施、住宅汇总（不逐栋建模）、特殊地点（可能非居住区）、风格与因果解释 | 编辑骨架或社会经济后 |
| 4. 故事候选 `story` | 事件候选、线索、秘密、开放问题 | 编辑前三任一后 |

**保存上游阶段 = 下游清空并标为失效**，不会留下悬空引用。必须逐段重新生成（一次只推进一段）才能发布。

## 输入（都要显式给出）

世界包 revision、`seed`、地点（手填地形样本或已选地点）、地图输入（`input_version` / `coordinate_system` / `scale`，V1 **原样记录不解析**，不假定未来工具格式）、地形（海拔/坡度/降水/温度/淡水/沃土/洪涝/面积/示意坐标）、水源（类型/可靠度/日供水量/蓄水/距离）、交通（道路等级/水路/人背/年封闭天数/到市场天数）、资源候选（丰度/可接近度/**是否已勘探**/是否可采/所需技术/燃料）、允许材料与允许技术、文化模板（只管屋面/取暖/户规模）、体型模板（只管层高与空间系数）、社会模式与证据、进口依赖、元素绑定（请求内显式 ID + 版本 + 有界快照）。

**不会发生**的事：没选中魔法/蒸汽就绝不生成锅炉房或护持塔；未勘探的资源绝不变成产量或库存；允许材料里没有的材料绝不出现。

## 校验（发布前全量跑一遍，零写入拒绝）

- 严格数值：`bool`、`NaN`、字符串数字、未知字段全部拒绝（`extra=forbid` + `strict=True`）。
- **派生值不信阶段数据**：水源/本地粮食/进口粮食/运输承载从输入重新推算，必须与骨架记录一致；"把所有上限一起改大"会被拒。口粮需求必须等于人口×人均口粮。
- 人口：组群占比之和 = 1000‰，总数不超过水源与粮食承载，必须有少数/多数角色，组群 ID 不重复。
- 劳力：可用劳力 = 人口 × 450‰（重新核对）；`assigned_workers` 必须**等于各生产链工人之和**；产业工人不得超过可用劳力。
- 资源与生产链：输入必须有**已勘探且可采**的来源（未勘探的候选不能进链）；声明燃料能源就必须有已勘探的燃料或燃料进口；铁矿/铜矿/砖/盐这类需要加热的产出必须有燃料；技术必须已申报。
- 供需口径：本地口粮不得超过粮食链实际产出；可用量 = 本地 + 进口 − 出口 − 生产投入，必须覆盖需求。**全部用整数克/年比较，没有任何取整容差**——差一克也拒。口粮需求只允许 `t/year` 或 `kg/year`，且必须精确等于 `人口 × 180 000 克/年`（即每人每年 0.18 吨 = 180 公斤）；人口因此落在 50 人网格上，使该值可用整数千克表示。等价的吨／千克换算可以通过；只改单位却不换算数量、或修改周期/数量使实际需求变小，都会被拒。
- **口粮基准（可直接核算）**：1 人 · 年 = 180 000 g；1 000 人 · 年 = 180 t；因此 180 t/年的进口只够约 1 000 人（不是一百万），而 180 kg 只够 1 人。`tests/test_towns_units.py` 用**手写数字**独立断言这些关系，避免"常数错了自己的测试也跟着错"（此前正是把 180 000 误写成 180，导致进口承载放大一千倍）。
- 出口按**资源累计**核对：拆成多条各 60% 也会被合并成 120% 而拒绝，不会因为单条都没超标就放过。
- 进口按**声明额度累计**核对：每条进口的物资种类、单位、周期必须与声明一致，多笔合计不得超过该声明的 `amount_per_period`（一个额度不能重复吃满）；`via` 必须是**已声明的通路**（道路/水路/人力背运），"teleport" 之类会被拒。
- 资源可用性是**有界不动点**（生成器与校验器共用同一份，两者不可能不一致）：起点 = 已勘探 + 可采 + 自身技术满足且**不需要燃料**的资源，外加**数量为正**的燃料进口；每一轮把"燃料已被满足"的资源加入，最多 N 轮（N = 候选数+1）必然终止。因此依赖链能解开（木 → 煤 → 铁），而无外部起点的循环（煤要木、木要煤）**不会自举**，并在作者视图里给出原因。
- 「许可」与「实际来源」严格分开：允许材料表里写着 coal **不等于**有煤；零数量的燃料进口不算来源。
- 引用与可达：街区/设施/特殊地点/事件里的 ID 必须存在，街区必须有可达道路，势力关系与隐藏目标引用必须有效。
- **各组 ID 分别唯一**：道路、街区、设施、势力、生产链、贸易条目、特殊地点、人口组群、事件、线索、秘密各自检查。
- 特殊地点不得被当作居住区；住房汇总必须能容纳人口。
- 候选事件**不得**被自动标记成可执行任务或奖励。

失败时**什么都不写**：请求在内存里被拒绝，草稿、版本与绑定都不会留下半成品。

## 可复现

同一 `seed` + 同一输入 + 同一基础故事包 revision ⇒ 同一座城镇，**包括每个实体的 ID**。生成只用一个 SHA-256 计数流，不用 `uuid`、不读时钟、不用内置 `hash()`。重启后读取草稿得到的快照与原快照逐字节相同（有测试）。

## 版本与发布

两个**独立的显式动作**，各自幂等：

1. **发布** `POST /api/inner/towns/{draft}/publish`（带 `expected_revision`）
   → 生成不可变 `town_version`，内容哈希即 ID。同内容重复发布会复用同一行（`reused: true`）；`publish` 本身会推进草稿 revision，并在**同一个 SQLite 事务里重查 CAS**，所以两个写者不会互相覆盖阶段。
2. **采纳** `POST /api/inner/town-versions/{version}/adopt`（带 `expected_story_revision` 与可选 `location_id`）
   → 通过既有 `Runtime.commit_package` 事务写进故事包新 revision 的 `mechanics.towns`，故事包**自带完整快照**。

顺序是：校验版本 → 核对固定基础版本与世界身份 → 已采纳则只补索引并返回 → 提交故事包 → 一个短事务写绑定索引。`commit_package` 之后、索引之前中断，同一请求重试会**只补索引、不新建版本**（测试覆盖）。

**不做的事**：不覆盖旧版本；不把旧草稿悄悄挂到新世界上（基础版本变了直接报冲突）；V1 **不允许跨世界采纳**（不同故事包 id 会被拒），要换世界请对目标世界重新生成。

## 信息边界

玩家侧 `/api/sessions/{id}/towns` 有两层过滤，缺一不可：

1. **版本过滤**：只读该旅程绑定的那个 story package revision，绝不读草稿表，也绝不按 `town_id` 跨库查。
2. **已知范围过滤**：只返回
   - 当前所在地（`knowledge = current`，完整公开细节）；
   - 旅程真正到过的地点（`explored`，完整公开细节）；
   - 当前地点的**相邻**地点（`nearby`，只有名称/类型/区域，明确标注"尚未到过，细节未知"）。

   未到过也不相邻的地点**完全不返回**，连名字都不出现。作者放在库里但没绑地点（`location_id = null`）的城镇永远不进玩家投影：库里的东西不等于世界里的东西。

单对象端点 `/api/sessions/{id}/towns/{version_id}` 用同一套过滤，猜 version_id 也拿不到没到过的地方（返回 400）。

公开投影字段级规则（三条互相独立的轴）：

| 轴 | 字段 | 含义 |
|---|---|---|
| 是否被知道 | `visibility` = `public` / `author` | `author` 表示本地人也不知道，玩家投影里整条消失 |
| 能否进入 | `access` = `public` / `restricted` / `secret` | **只影响 `enterable` 标记**，不影响是否出现：知道有一条私巷，不等于能进 |
| 通行状态 | `status` = `active` / `dormant` / `sealed` / `ruined` | 封闭的已知遗迹仍会被描述为"封闭、不可进入"，而不是被抹掉 |

- 设施（facility）**继承所在街区的可见性**：某个街区是 `author`，它里面的设施也不会因为自己有公开名字而泄露这个街区的存在。
- 秘密（`secret` / `hidden_goal` / `secret_note`）永远不进公开投影。
- 公开 `warnings` 是一句固定的估计免责声明：**不含内部警告文本，也不含条数**（条数本身会暗示藏了几样东西）。
- 模型上下文只增加一个 `town_summary`（≤1200 字符），而且只针对**当前所在**且能读到的城镇。
- 旧旅程持有自己的 `session['revision']`，新采纳只产生新 revision，旧旅程看不到新城镇。
- 故事包导出后可在空数据库里重新导入并照常读取城镇（快照随包走，不依赖 town 表的隐藏数据）。

## 已知边界（不要当成已实现）

- 没有接任何语言模型：`docs/local-engine-design.md` 里"模型只提候选"的位置留了接口思路，但本版**不调用**。
- 没有接外部地形生成器；`map.scale` / `coordinate_system` 只是原样记录。
- 系数（每 km² 产粮、人均口粮、人均用水、道路承载、每劳力产量等）是**玩法假设**，不是历史统计；真实档里也只主张因果方向，不做定量复原。
- 候选事件需作者按现有严格 schema 写成故事事件才能游玩；V1 不自动编译成任务或奖励。
- 资源/社会反馈是**有限阶段约束**：不迭代收敛、不循环重试到"看起来对"为止；得不到就给警告或拒绝。
- 只做本机单作者，不做多用户权限隔离；跨世界复用不支持。
