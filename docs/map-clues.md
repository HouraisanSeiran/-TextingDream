# 地图迷雾上的「大致位置」线索（place_clue）

## 地图上的样子（2026-11 更新）

迷雾不是纯黑遮罩，也不是服务器画进底图的花纹，而是**浏览器按真实揭示几何画在底图上方的一层
灰蓝卷云墙**（`app/static/map-fog.js`）：

- 服务器（`app/fog_art.py`）只负责**安全那半**：揭示圈外的底图像素一律填同一个常量色
  `FOG_RGB`，不含任何地形信息；同一套 rough edge（半径 0.80–0.97）也随投影 JSON 发给客户端。
- 客户端拿到 `fog.reveal`（圆心、半径、edge 轮廓）后，用**同一个公式**算 ratio，再画云：
  贴着地图是一道细小浅灰蓝的扇贝云缘，往里是中尺度的灰蓝云岸，再向外是更大更暗的
  灰褐/炭灰云层，所以可见区总是被一圈近似圆的云墙包住，边缘局部鼓起/凹进。
- 画风参考《天国：拯救》系列地图上那圈手绘云墙的**风格**（深灰蓝卷云墙、云层互相遮挡、
  内部有很淡的褐/炭灰卷云细弧）；没有裁用任何游戏截图素材，也没有水印。

安全性不变，而且是硬约束（有测试盯着）：

- ratio ≥ 0.985 的像素**一定** alpha=255（完全不透明）——客户端显示的范围永远不会比服务端揭示的多；
- ratio ≤ 0.93 的像素完全不画（可见区里不铺任何装饰）；
- 中间那道雾边只会**向内收**；底图矩形以外一个像素都不画。

回归测试：`tests/test_fog_alpha.py`（在 Node 沙箱里跑真正的绘图代码）覆盖
**三个地区 × zoom 1/2（底图缩放）× dpr 1/2（设备像素比）× 单圆/全部圆**，共 24 个场景，
同时验 `ratio≥0.985` 与 `ratio≥1` 两档 alpha 不变量、矩形外不画、以及可见区内被雾盖住的
像素占比（`insideCoveredPct`）<50%；另有 `tests/test_fog_art.py`（服务端雾字节与地形无关）。
独立预览：`/static/map-art/fog-preview.html`（真实地形夹具 + 地点/线索叠层）。

## 玩家看到什么

迷雾规则不变：只有去过的地点、当前所在地和相邻地点周围是可见的，其余像素由服务器直接画成雾色。

线索是叠在雾上的一个**虚线金色圈 + 问号**，旁边写着称呼（例如「传闻中的沉船藏宝地」）：

- 真实地点**一定在圈内**，但**不在圆心**。圆心偏离真实位置 25%–80% 半径，方向随机。
- 圈内依然是雾，线索不揭示地形；玩家得自己走过去。
- 走到该地点（进入 `explored`）后，线索自动消失，地点按普通迷雾规则显示。
- 同一地点拿到第二条线索时，圈会落在另一个位置；两圈的交集能帮玩家缩小范围。

## 作者怎么写

线索是一个效果 op，可以写在事件动作的 `effects` / `success` / `failure` 里，也可以写在任务（`mechanics.quests`）的 `effects` 里：

```json
{"op": "place_clue", "place": "hidden_hoard", "precision_km": 200,
 "label": "藏宝图上的X", "text": "老水手说沉船就在南边那片礁石附近"}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `place` | 是 | 故事包里的地点 id。地点必须有 `coordinates`（城镇、藏宝地、遗迹都行）。 |
| `precision_km` | 否 | 模糊半径，10–2000 km，默认 150。越大越不准。 |
| `label` | 否 | 玩家看到的称呼，≤40 字。不写时：地点公开就用地点名；地点被保留（`visibility: author` 或 `reveal_flag` 未置位）就显示「传闻中的某处」。 |
| `text` | 否 | 线索原话，≤200 字。会同时写进玩家的「所闻」记录（未证实）。 |

藏宝地这类特殊地点可以直接写成 `visibility: "author"` 的普通地点，不连入 `neighbors`：玩家只能通过线索知道「大概在哪」，真名和 id 都不会出现在玩家投影里。

## 实现位置

- `app/map_clues.py`：校验、偏移计算（按旅程种子 + 地点 + 第几条线索确定，重放结果一致）、玩家投影。
- `app/runtime.py`：`place_clue` 进入事件动作白名单与 `_apply_effects`。
- `app/quests.py`：任务效果支持 `place_clue`。
- `app/play_map.py`：投影 JSON 多一个 `clues` 数组；裁切框会扩到能画下线索圈，但**揭示掩膜不变**。
- `app/static/play-ui.js`：玩家地图叠层画线索圈与图例。
- `app/static/map-fog.js`：灰蓝卷云墙（三层极坐标云岸 + 卷云细弧），只读 ratio 与 cloud_deg，不读地形。
- `app/static/map-art/fog-preview.html` + `fog-preview.js`：独立预览，真实地形夹具 + 地点/线索叠层；
  旧资产预览（`map-art/index.html`）不再内嵌合成雾样张，只保留线索圈画法。
- 测试：`tests/test_map_clues.py`（真实地点在圈内且不在圆心、被保留地点不泄露 id/真名/坐标、线索圈内 PNG 仍是雾色、确定性、到达后消失、包校验）；`tests/test_fog_alpha.py`（客户端雾的 alpha 硬约束）。

## 没做的

- **自由对话不会自动产出线索。** 目前线索只来自作者写好的事件动作和任务。让模型在聊天里“临场”给出线索需要一套结构化产出与审核，本轮没做。
- 线索不会随时间失效或被证伪，也没有「假线索」（圈里其实没有）。需要时可以加 `expires` 或 `false_lead`。
- DreamTerra 链路（`mechanics.dreamterra`）的投影还没接 `clues`。
