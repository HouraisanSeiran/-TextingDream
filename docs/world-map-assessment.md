# 世界地图细节与城镇分级评估

日期：2026-10-30。范围：世界地图；城镇内部地图不变。

## 结论

现有 civ 引擎能够支撑城镇分级显示、随缩放细化的河流和地形绘制，无需替换生成器。原宿主只绘制一次导出底图，然后通过 CSS 放大，没有接入完整的原生视口绘制。城镇过密还来自打开了调试城址圆点。

本轮已修复世界地图显示接入；没有重新生成或修改已登记世界，也没有增加原件中的河流数量。新增真实支流和特殊地形仍需要扩展生成规则。

## 已完成

- 关闭全部城址调试圆点，复用原生城镇符号、当年人口/级别、名称和碰撞避让。
- 总览最多选择 12 座国都/大城作为候选，按原生重要性与人口顺序选择；重叠时进一步避让。
- 1.5 倍开放其余国都/大城，2 倍开放城市，3.2 倍开放小镇，6 倍开放村落。名字还遵守原生文字门槛与避让规则。遗址/关隘至少 3.2 倍出现。
- 缩放超过 1.2 倍，接入原生地形和文明细节绘制：河流、海岸、山林符号、国界与道路按视口重新绘制，文字使用屏幕分辨率。
- 同一城镇不会因缩放随机出现、消失或换位置；变化的是显示范围和密度。
- 仓内宿主补丁副本同步更新。

入口：`external/civ-atlas/src/dream/host.tsx` 的 `WorldViewport`。

## 源码能力与缺口

| 目标 | 现有依据 | 评估 |
| --- | --- | --- |
| 城镇随缩放分级 | `render/civ/settlements.ts`、`render/labels/settlements.ts`、`render/labels/draw.ts` | 已有完整基础，本轮完成宿主接入和总览限量 |
| 放大看到更多河段 | `render/common.ts` 的 `riverLod`、`render/fantasy.ts` 的 `fantasyRiverStyle` | 全图只显示流量约高于生成门槛 4.5 倍的河段，约 3.2 倍放大后降至生成门槛；本轮恢复该行为 |
| 生成更多真实河流 | `gen/world.ts` 的汇流与 `traceRivers` | 可扩展。当前门槛为 `10 * (n / 36000)`；提高地块数不会自动保证河网更密。应增加可保存的河网密度参数并检查下游流向、入湖/入海和道路跨河关系 |
| 山地、高原、峡谷 | `gen/world.ts` 的板块、侵蚀、高原底座沿水系让路 | 有真实高度数据和高原切谷逻辑，不只是画山形图标；但没有独立的可交互峡谷地点系统 |
| 森林、荒漠、冰原等 | `gen/biomes.ts` 的温度/降水分类 | 已支持，细节绘制可以直接复用 |
| 湿地 | `gen/biomes.ts` 定义 Wetland，但 `classifyBiome` 无对应返回分支；`gen/world.ts` 使用该函数逐格分类 | 当前基础自动生成链缺少湿地判定；建议结合低坡度、汇水、地下水或洪泛条件补齐 |
| 自然火山 | `gen/world.ts` 的 `volcanoes` 由地形编辑操作调用 `volcanoPeaks` 得到 | 编辑能力存在；默认自然生成不会保证火山，需要基于板块/热点补充生成 |
| 瀑布、喀斯特等 | 本次检查未找到相应专用生成流程 | 需要新规则、持久化表达及表现层，不能算现成功能 |
| 建筑尺度真实地形 | 世界逻辑画布为 2048×1024，默认生成目标 16000 地块；`gen/gully.ts` 主要提供渲染沟壑细节 | 放大不增加世界拓扑。建筑尺度移动若要受坡度、河道阻挡影响，需要独立局部地形数据 |

## 推荐后续顺序

1. 增加河网密度参数，保留旧原件；新建世界时生成更完整的支流水系，并验证河流与道路的连接。
2. 优先补湿地、洪泛平原、自然火山等能由已有高度、水系和板块数据推导的地形。
3. 为特殊地形增加地点身份和玩法影响，例如渡口、山口、洪泛风险和通行代价，再扩展瀑布、洞穴等独立地点。
