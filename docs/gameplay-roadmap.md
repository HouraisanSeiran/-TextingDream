# 可玩性扩展建议（基于 2026-11-01 代码盘点）

现状：事件 → 检定 → 效果 → 奖励 → 时钟/压力 → 结局 这条主线已经接通；地图有服务端迷雾和「大致位置」线索。
下面按「数据或后端已经有、只差接线」优先排序。工作量：小 = 一两天，中 = 三到五天，大 = 一周以上。

| # | 玩家体验 | 复用的现有模块 | 主要改动 | 工作量 |
|---|---|---|---|---|
| 1 | **任务栏**：NPC 发委托，接下、完成、超时失败，领奖励 | `app/quests.py`（状态机、证据、报酬校验都写好了，有测试） | 运行时还没调用它：包校验加 `quests.validate`；`surface()` 加任务视图；每次推进时钟后调 `quests.expire`；加接受/放弃/提交路由；前端任务面板 | 中 |
| 2 | **藏宝闭环**：听到传闻 → 地图出现线索圈 → 去找 → 到达后「搜寻」检定 → 开出宝藏 | `map_clues`（已完成）、事件检定、`rewards` 随机装备 | 主要是写一个示例世界和测试；可加一个通用「挖掘/搜寻」动作模板。注意线索到达后会消失，宝藏要绑在到达事件上 | 小 |
| 3 | **对话给线索**：向酒馆老板打听，地图上出现圈 | `scene_judgment`（模型只能在作者选项里选）、`adventure_actions` 的话题/回答、`place_clue` | 话题的回答分支和场景判定选项允许挂 `place_clue`；模型只能从作者已声明、带坐标的地点里选 | 小到中 |
| 4 | **对话触发委托**：聊到某个话题，NPC 提出任务 | 同上 + `quests.propose` | 依赖 #1；话题或选项加「提案任务 id」字段 | 中 |
| 5 | **昼夜影响**：夜里赶路更慢更危险、检定更难；有些 NPC 夜里不在 | `geography.is_daylight`、`travel_hours`、`drama.resolve_check`、NPC 日程 `Routine` | 夜间旅行耗时系数、夜间检定难度修正、动作条件支持 `daytime`；作者可配置，默认关闭，老存档不变 | 小 |
| 6 | **旅途遭遇**：路上遇到劫匪、商队、塌方，要检定或选择 | `Runtime.move`、确定性骰点、事件系统、civ 路线类型（大路/小径/海路） | `mechanics.encounters` 声明（按路线类型、地形、昼夜加权）；`move` 里用种子掷遭遇，命中就进入预设遭遇事件；回滚和重放结果不变 | 中 |
| 7 | **采集资源点**：矿点、林地、渔场，到达后花时间和体力采集，得到材料 | `local_rules` 资源账本、`rewards` 材料、地图美术资源图标、城镇资源候选 | 资源点作为带坐标的地点或地点属性；加「采集」动作；地图叠层画资源图标（未勘测的用虚线圈） | 中 |
| 8 | **天气**：下雨天旅行变慢、观察变难，特定天气才触发某些事件 | 日历、种子派生、civ 每格气温/降水/群系 | 新增 `weather.py`（按种子 + 日期 + 气候带算，不存状态）；`surface` 加天气；接进旅行耗时和检定；没有气候数据时不显示天气 | 中 |
| 9 | **声望/好感可见**：NPC 对你的信任度有显示，影响报价、透露信息 | `session['development']` 里已有 trust，NPC 卡、场景判定 | 玩家侧投影一个粗粒度好感等级（不露具体数值）；动作条件支持好感门槛 | 小到中 |
| 10 | **城镇贸易差价**：A 镇低价买、B 镇高价卖，商路被封会涨价 | 城镇产业/交通、`rewards` 货币账户、路线耗时、压力事件 | 新增 `market.py`（整数公式、确定性）；买卖动作（`give` 目前没有执行器，可一起补）；交易面板；先做「只有差价、没有库存」的最小版 | 大 |
| 11 | **补全 `give` 动作**：把物品交给 NPC 完成交易、贿赂、送礼 | `adventure_actions` 已有类型定义 | 写执行器：从背包移除物品、触发作者声明的效果 | 小 |
| 12 | **知识点记录簿变成可操作线索**：记录里的地点能一键在地图上定位 | `knowledge.notebook`、`map_clues` | 记录条目带地点或线索 id 时，前端加「在地图上看」 | 小 |

## 建议顺序

1. **#2 藏宝闭环 + #3 对话给线索**：改动最小，直接用上刚做好的迷雾和线索，体验提升最明显。
2. **#1 任务栏**：引擎已有测试，接线后很多玩法（#4、#10）都能挂在它上面。注意 `app/quests.py` 在 git 里有未提交修改，接线前先确认它已定稿。
3. **#5 昼夜 → #6 旅途遭遇 → #8 天气**：三者叠加让「旅行」本身变成玩法。
4. **#7 采集、#10 贸易**：要新的状态与账本，放在后面。

## 约束（沿用现有设计）

- 模型只在作者给定的选项里选，所有状态变化由引擎结算；模型不能自由创造地点、任务或物品。
- 所有随机都从旅程种子派生，回滚和重放结果一致。
- 新机制默认关闭，老故事包和老存档的行为不变。
