# 模型输出规范

更新日期：2026-11-13。适用于本地与远端模型。输出上限由 [token_budget.py](../app/token_budget.py)集中定义，经[请求层](../app/provider.py)应用；本文与代码同步维护。本轮统一输出，不实现模型输入分词或自动窗口适配。

## 1. 名称和单位

| 名称 | 单位 | 含义 |
|---|---|---|
| 输入用量 | token | 模型服务报告的输入数量，通常为 `usage.prompt_tokens` |
| 输出用量 | token | 模型服务报告的生成数量，通常为 `usage.completion_tokens` |
| 输出上限 | token | 单次请求允许生成的最大数量；不是目标长度，也不是总窗口 |
| 总上下文窗口 | token | 模型服务单次请求的实际容量，包括输入、生成及对应模板等开销 |
| 输入字符预算 | 字符 | 工程的 `context_chars`，限制部分流程输入规模；不等于分词后的 token 数 |
| 正文长度 | 字符／中文字数 | 产品表达与校验要求，例如现场叙述通常80～180字；不用于计算账单 |

文档中4K、8K、16K、32K分别指4096、8192、16384、32768 token。设置项优先写精确整数。不同模型分词不同，不用“一个汉字固定等于几个 token”统一换算。

## 2. 默认输出档位

| 档位 | 输出上限 | 任务与代码 scope |
|---|---:|---|
| 极短 | 256 | 连接检查 `connection_test`、合法动作匹配 `intent` |
| 短对话 | 1024 | 游玩叙述 `surface`、玩家台词草稿 `player_reply` |
| 清单 | 2048 | 背景采用资料选择 `background_select` |
| 一般创作 | 4096 | 文明偏好参数、国家背景、大陆背景、世界总概；资料条目与人物卡草稿；`inner`、`development`；旧 `generator_*` |
| 大批创作 | 8192 | 背景环境、资料整理、历史叙述；旧单地区历史／政治／设定；旧 `world_stage_*`；归档润色 `polish` |

1024是每次请求的完整输出预算：现场叙述的JSON括号、字段名、人物反应列表也占空间。它不要求每轮写满1024 token，不改变已有80～180字的叙述目标。普通文本叙述与JSON现场叙述采用相同默认档位；没有按文本长度硬切回复。

本轮将原有分散的260、900、2000、2500、3000、4000、5000、6000、7000、8000等默认预算归入上述档位。显式指定的自定义数值继续有效，不强制把旧草稿重写成档位数值。

## 3. 配置优先级和兼容

单次调用的显式 `max_tokens`／生成请求的 `output_tokens` **优先于任务默认值**；未登记任务使用旧API设置中的 `max_tokens` 作为后备值，默认8192。旧API设置不是所有任务的统一硬上限。已登记任务即使旧API设置为1200，仍使用自己的默认预算；需要调整某项时，修改集中定义或由调用处显式指定。

请求层拒绝非整数、布尔值、零、负数以及超过65536的显式预算。对外旧生成请求仍保留至少1500的约束：城市／事件／世界草稿默认4096、最多8192；四阶段世界草稿默认8192、最多16384。原来8000／16000以内的自定义请求与已保存数值仍合法。

沿用现有协议字段：兼容接口发送 `max_tokens`，Anthropic适配器也使用该字段；不为统一中文名称批量改API字段。返回的 `usage` 保留供应商原始字段并作现有归一化，不能把“请求的上限”当成“实际输出”。

## 4. 内容与失败处理

- 普通游玩路径返回正文；现场叙述返回 `narration` 与合法 `reactions` 的JSON，经过已有校验后才提交回合。
- 意图匹配只返回合法动作ID或空值及简短理由；台词草稿不自动发送。规则决定检定、资源、时间与后果，模型负责表达。
- 模型不能把玩家未说出口的内容当作NPC已经听见，不能把猜测自动写成已确认事实。
- 达到上限而被服务标记 `finish_reason=length`／`stop_reason=max_tokens` 时拒绝结果，不能拿半段JSON或半句回复推进状态。已有作者草稿重试行为各自保留；本轮不新增无限重试。
- 输出包含思考时，按具体服务的计量语义核对是否占生成预算；关闭本地思考应使用模型服务支持的模板设置，不能只依赖提示中的 `/no_think`。

输出上限调整不保证模型遵从规则，也不解决输入过长。应满足：**实际输入token＋输出预算＋模板等开销≤服务实际总窗口**。当前输入分批主要使用字符预算，仍需按具体模型检查；4K服务不适合直接执行8192输出预算的背景任务。

## 5. 观测与验证

用量缺失显示未知，不补成零。跨模型同时记录实际token、可用中文字数与端到端耗时。当前请求为非流式，工程记录的总耗时不能当作首token时间或纯解码速度。统计边界见[模型用量评估](token-usage-evaluation.md)。

自动回归与本机模型验收分开记录，步骤见[本地模型对话测试](本地模型对话测试.md)。模拟HTTP通过只证明请求和存档处理，真实连续对话质量必须另测。
