# 三个可玩短篇

每篇以 **15–20 分钟**为设计目标：约 12–18 次行动，穿插 6–10 轮对话、阅读和选择。没有进行人类玩家计时，快速点击按钮会明显更短；自动回归耗时不能当作游玩时长。

## 从哪里开始

服务运行后刷新首页，在左侧旅程中选择以下标题。每篇都是独立的世界版本与存档，人物、钱包、后果互不串联。

| 片段 | 目标与主要选择 | 建议试问 |
|---|---|---|
| 铜杯酒馆：一条衬裤的风波 | 找运货单、挣旅费；可以买酒、帮忙，也可以偷取、炫耀、归还和修复关系 | “如果我不拿报酬，你愿意介绍船工吗？”“我想偷走衣服然后炫耀。” |
| 雾桥：八便士的路 | 护送药箱；核实维修情况后付钱或帮工换票，观察无证据指控的后果 | “为什么药箱也要交费？”“如果我帮忙，能不能免票？” |
| 雨后粮市：最后一袋麦子 | 核对品质、议价、购买、送货，决定利润留给自己还是分享 | “受潮和下毒是一回事吗？”“诺尔愿意付多少？” |

普通交流使用“说话”通道；内心想法使用“内心”通道。要执行操作，点击行动按钮，或在“想做但上面没列出的事”输入意图，查看候选后确认。第一版的自然语言理解只能选择当前已声明的动作，不会自动编译任意新规则。

每幕用明确的“离开/交付/过桥”等行动结束。之后场景卡显示“前往……”按钮；通过地点按钮进入下一幕。短篇不依赖尚未接通的玩家原生地图，也没有把三个地点伪装成真实 civ-atlas 地理。

场景卡会显示旅费和暂持物。以便士为唯一记账单位：12便士=1先令，20先令=1镑。麦酒2便士、桥费8便士等都是游戏设计价格，不是英国历史物价考证。收入来自明确的委托与一次性劳动；此版不模拟完整商家库存与财政。

## 这次验证的玩法

- **同一行为可以有不同反应**：模型读取角色价值观、现有对玩家的信任、当地规则、实际观察和已结算结果，在场景允许的后果中选择。
- **检定仍由原系统负责**：属性、疲劳、难度与确定性掷骰均沿用 `attribute_v1`。
- **风险先确认**：偷取、炫耀、公开指控都需要服务器核对确认凭据。
- **胡闹拆步骤**：偷取成功不自动炫耀；成功且未被看到不生成目击反应；偷取失败不能继续展示未取得的衣物。
- **报官不等于即时惩罚**：模型可选择受害者决定报官，但不会凭空让卫兵到场、扣罚款或坐牢。
- **不同维度分别保存**：人物信任写入既有 `development.relationships`；钱与货物写入既有资源账本；公开后果进入信息层；全部随旅程归档和回滚。
- **错误不落成事实**：模型返回未知角色、未知反应、重复观察者或过期状态时，本轮不提交。正文事实准确性仍需评测，结构校验不能证明每一句话都正确。

## 本地模型与离线模式

本轮验证使用现有 `D:/llm/qwen3/models/Qwen3-4B-Q4_K_M.gguf`，由 llama.cpp 在 `127.0.0.1:8082` 提供服务，8,192 token 上下文、单并发、关闭思考模式。织梦连接地址为 `http://127.0.0.1:8082/v1`，模型名 `qwen3`。

**本地模型对话需要关闭应用的“离线模式”**。当前 Provider 需要非空密钥，无鉴权的本机服务使用占位值 `local`。密钥仅在进程内存；应用重启后需要重新填写，或以环境变量传入本机占位值。没有更改全局云端配置默认值。

真正的离线模式采用作者写好的第一项反应与结果文本，不调用模型。它用于检查流程，不能作为模型理解能力的证据。

## 源码与复现

内容维护入口为 `tools/playable_scenes.py`，导出的三个 JSON 是可读故事与角色资料。修改内容后导出：

```powershell
python -m tools.playable_scenes
```

服务已启动时，安装故事并创建三段新的旅程：

```powershell
python -m tools.playable_scenes --install http://127.0.0.1:8000
```

这条命令每次都会创建新旅程。若原先有当前世界，结束后恢复其激活位置；既有旅程继续绑定原版本。没有当前世界时保留最后安装的短篇为当前世界。

规则与流程回归使用临时库：

```powershell
python -m unittest tests.test_short_scenes tests.test_empty_world_startup tests.test_encyclopedia_attributes tests.test_drama.DramaTests.test_formula_determinism_bounds_and_validation
```

本地模型已在 8082 启动后运行真实小样本验证：

```powershell
python -m tools.evaluate_short_scenes
```

记录保存在 `artifacts/playable-scenes/model-evaluation.json`，包括逐次时间、结果与请求响应追踪。它只使用临时旅程，不推进玩家的正式存档。合成性格/信任对照同时改变了两项参数，不能据此区分哪一项单独造成差异，也不能由一次选择推断稳定成功率。

## 验收时值得观察

1. 开局是否立即理解目标，以及钱够不够。
2. 是否愿意主动问人物问题，而不只是依次点按钮。
3. 做坏事后的反应是否符合对方性格；修复关系是否有意义。
4. 检定失败时有没有下一条可走的路。
5. 交易、物品归还与回滚后，页面显示是否与实际余额一致。
6. 阅读与思考后的真实耗时是否达到目标；如果只需几分钟，优先丰富冲突和人物交流，不靠强制等待凑时长。

未包含：通用自由动作编译、多角色主动对抗、完整目击传播和司法程序、稳定的模型心理学模拟。短篇中的可选后果仍由作者定义；本轮验证的是“参数驱动的模型选择”能否嵌入现有规则闭环。
