## 一、所有专题共用的采集清单

每个资料条目或变体需收集以下内容；不适用项标明不适用，未知与待核单列，不用0代替未知。

1. **身份与分类**：稳定ID、已有namespace/id、名称、别名、一个主标签、次标签、集合/模板粒度。
2. **完整定义**：是什么、不是什么、机制、前提、例外、用途、影响与后果。
3. **适用背景**：地区、时期、文化、气候生态、科技/魔法条件、使用规模、传播与普及程度。
4. **关系**：原料、产物、技能、设施、能源、服务、组织、替代、变体、冲突、反制、上下游。
5. **获取与发展**：采集/购买/学习/制造/研发/继承/发现的条件，原型到普及的瓶颈。
6. **数值基础**：数量、单位、范围、时间基准、规模假设、品质档位与适用条件。
7. **运行参数候选**：成本、工时、周期、容量、消耗、损耗、维护、耐久、产出、恢复、失败及后果等适用项。
8. **交互与规则候选**：可执行动作、前置状态、输入输出、目标/范围、结果分支、叠加/互斥/上限；未接引擎的明确写为设计提案。
9. **证据**：具体来源、实际访问状态、支撑哪项断言、地域时期、权利说明、原创/推演范围。
10. **缺口**：未核断言、争议、缺失数值、跨组依赖、需要作者决定的问题。

单位沿用公制，物品重量整数克、游戏价格整数铜币，10铜=1银、10银=1金。低于最小货币单位的定价单列待决，不私设新币制。历史原始单位与现代换算、游戏价格分开保存说明。

## 八、可复制给采集智能体的交付要求清单

- 领取明确的专题编号、子范围及独立文件；同一概念优先引用现有ID，不并行重写公共索引和他组文件。
- 每组提交：**条目候选JSON、可读Markdown、参数表、关系表、来源与未解决问题清单**。文件形式按该组现有格式适配，不私自升级全库schema。
- 参数表列：参数含义、单位、范围/分布、规模与时间基准、适用背景、事实/估算/游戏设计性质、来源、置信与待核项。
- 关系表列：起点ID、关系、终点ID、方向、条件、数量/单位（适用时）、来源/设计说明。未建条目标单列待补，不冒充已解析。
- 原创玩法数值允许提出，但必须标成**待平衡设计提案**；不能把成功率、掉落率、魔法效果伪装成网上查到的客观事实。
- 不以固定条数凑数；每个专题说明已覆盖、未覆盖和后续扩展列表。现实/历史资料兼顾不同地区时期，不全套套用中世纪欧洲或现代中国。
- 保持needs_review/needs_detail候选状态；实际读到的正文才能记read；链接、摘要、许可和事实审查分别说明。
- 只提交分配范围的候选材料；**不改库、不改故事包、不改引擎、不启动服务，不自动将素材采用到任何世界**。
