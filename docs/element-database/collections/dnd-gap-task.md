# 任务：补齐 D&D 对照下的仪式、种族、冒险内容

日期：2026-11-12。状态：**待领取，未开工**。分派依据：用户要求把缺口记录成任务，交其他智能体实现。

本文件是任务卡，不是已实现的规格，也不是对任何数值的确认。领取前先读本文第五节的边界；与既有文档冲突时，以 `docs/element-database/README.md`、`collection-master-list.md`、`docs/units.md` 和当前代码为准。

## 一、结论（先读这段）

织梦缺的不是名词，是**能开一局的玩法包**。元素库约 2200 条，全部 `needs_review` / `needs_detail`。作者开局可以锁定条目进故事包，但 `app/element_assembly.py` 明确不把百科条目编译成法术、奖励模板或配方。`docs/element-catalog/western.md` 还规定不收 D&D 专有名称、专有怪物名、职业等级、CR、属性值、法术位。所以本任务补的是**织梦自己的可玩结构**，不是搬运《玩家手册》。

判定与任务骨架已经存在，不要重做：

- 六项属性 0–100：`app/attributes.py`（天赋、力量、敏捷、智慧、社交、韧性），血量 `round(50 + 2×韧性)`。
- 可选 d20 四档检定：`docs/check-system-v2.md`，`mechanics.checks` 显式开启才生效。
- 任务、奖励、事件、冒险动作的契约分别在 `docs/quests-contract.md`、`docs/examples/rewards-使用说明.md`、`docs/events-contract.md`、`docs/adventure-actions-contract.md`。
- civ 开局已有 11 个传闻级事件和 6 个任务（`app/event_library.py`），完成证据基本是“到过某城”。真正可走通的只有送药和讨伐；讨伐的目标在作者侧是一头老熊，没有战斗结算。

## 二、现状（2026-11-12 核对代码与源文件，未构库、未改库）

### 2.1 仪式：有制度记述，没有可施放的仪式

已有条目都回答“谁有资格、授权从哪来、对社会有什么后果”，不回答“这一场怎么结算”：

- 东方：`religions.json` 的 `rel_zhaijiao` 斋醮科仪、`rel_fulu` 符箓、`rel_daoist_register` 传度授箓；`eastern.json` 的 `eastern_thunder_ritual` 雷法与召雷（证据链最弱的一条，雷部谱系与仪轨无一手文献）。
- 西方：`western.json` 的 `western_arcane_spellcraft` 奥术施法、`western_divine_miracle` 神术与神迹、`western_divination`、`western_curse_oath`、`western_necromancy`。
- 民俗：`steam-horror.json` 的丧仪残缺、节令祭仪、驱邪职。该组明确不写可执行的驱邪步骤。

职业侧有符箓师、阵法师、炼丹师、宫廷法师、学院学徒（`professions-fantasy.json`），是 NPC 工种，不是能力列表。

### 2.2 种族：有神话族类，没有可创建角色的种族包

- `fantasy-races.json` 22 条：巨人、巨怪、食人魔、半人马、萨堤尔、宁芙、人鱼、塞壬、独眼巨人、兽人（作为他称）、龙、那伽、药叉、罗刹、阿修罗、鬼、天狗、河童、狐、狐魅、鲛人。
- `races-supplement.json` 6 条：深井矿居族、机体嫁接者、运河船民氏族、炉火裔、魔偶劳役种、煤灯下的妖精。来源多在 `docs/wiki-collection-todo.md` 里待核。
- `western.json` 另有巨龙、精灵、矮人、侏儒与哥布林、妖精、狼人、吸血鬼。
- 主标签规范（`docs/element-catalog/primary-tags-spec.md` §2.1）按“有没有心智”判 `race`，所以龙、食人魔与精灵在同一类。无智兽仍是 `beast`。
- 城镇贴图支持 human / elf / dwarf / orc / halfling（`app/map_render.py`、`app/town_layout.py`），但**半身人没有元素条目**，orc 贴图对应的是“兽人：作为他称的敌人类别”，不是可玩模板。
- 没有任何种族特性接到六项属性、速度、感官或许可行动上。

## 三、要交付的三块

三块互不依赖，可并行领取。每块都要同时交**候选数据**和**接到现有契约的样例**，不能只交百科文字。

### 块 A：可施放仪式（对应专题 46，兼 32）

交付 12–20 条。其中至少 2–3 条是东方的符、阵或雷法，其余为西方奥术/神术母题的织梦原创名。

每条必须能回答，并落成结构化字段（字段名可在该块内自定，全块一致，不升级全库 schema）：

- 是仪式还是即时法术；施法时间（小时，对齐现有时钟，不发明第二套时间）。
- 材料或媒介：引用已有元素 id；没有就单列待补，不新造一套材料库。
- 目标与范围：自身、在场 NPC、当前地点、一条路线。不得要求引擎没有的“多目标选择器”。
- 一次检定：引用六项属性之一，给出 DC 或 difficulty 二选一，对应 `docs/check-system-v2.md` 的四档。
- 四档各自的效果：只用 `Runtime._apply_effects` 已支持的 op（`information` / `flag` / `resource` / `status` / `health` / `fact`）。做不到的效果写入 `unsupported`，不要虚构 op。
- 失败、打断、反制：各写一条，允许是“本版不支持”。
- 信仰记述与超自然生效分开：一条可以有社会后果（谁承认、谁惩罚），超自然效果必须显式标为世界自选规则，不写成史料。

样例要求：改写 `app/event_library.py` 的 `rain_ritual`，让“主持祈雨”变成一次可检定的仪式，而不只是赶到某城。改写放在样例文件里，**不直接改 `event_library.py`**，由后续接线任务决定是否采纳。

### 块 B：可玩种族包（对应专题 36）

交付 4 个可玩模板：人、精灵、矮人、半身人。半身人是新增（贴图已有、元素没有）。

每个模板：

- 体型、速度（相对人类的倍率或说明）、感官、语言、寿命阶段。
- 至少一项能改变判定或许可行动的特性，写明它改的是哪一项属性、哪个 DC，或许可哪个已有动作。不发明新属性轴。
- 与现有条目的关系：精灵、矮人引用 `western_elf`、`western_dwarf`，不重写其传说内容；半身人新建并说明无史实对应。
- 明确“这是玩家模板”，与块 C 的遭遇生物分开。

另外交一张**归类表**，不新建条目：把 `fantasy-races.json` 与 `western.json` 的非人族标成“可玩模板 / 遭遇生物 / 仅传说符号”三档，并写理由。龙、塞壬、罗刹、食人魔默认是遭遇生物，除非条目已写明有群体、语言与可谈判性（判据用 `primary-tags-spec.md` §2.1）。兽人条目是“他称的敌人类别”，不要直接改成可玩兽人；若要可玩兽人，另建一条并说明与该条的差别。

`races-supplement.json` 的 6 条来源未核完，本任务不把它们升格，也不把它们当可玩种族。

### 块 C：一场最小冒险（对应专题 37、38、43）

交付一套能串起来的样例，不是三个互不相干的清单：

1. **3 个生物**，每个都有三种解决：交涉、驱赶、战斗。写栖息地、规模、触发条件、士气或退却条件、以及每种解决引用的属性检定。攻防数值是**待平衡设计提案**，单独成表，不写进“事实”字段。优先复用已有生物（如狼群、山怪、巨蟒），不新造专名怪物。
2. **2 件装备**：一件武器、一件防护。重量用整数克，价格用整数铜币（10 铜=1 银、10 银=1 金，见 `docs/units.md`）。**不要用便士/先令/镑**，那是 `game-fields-spec.md` 的旧币制。写明耐久、有效范围、修理要求是设计提案。
3. **1 个任务**：不靠“走到就算完成”。完成证据至少包含一次检定结果或一个 flag，引用块 A 的一个仪式或块 C 的一个生物。结构对齐 `docs/quests-contract.md`。
4. **1 张遭遇表**：按路线或地形给出权重，说明哪些条件引擎现在没有（`docs/archive/handoffs/gameplay-roadmap.md` 记录旅途遭遇未实现）。标出“需新增”与“已有契约可表达”的分界。

奖励只引用已声明的 `mechanics.rewards` 形态。掉落权重是设计提案，不伪装成史料。

## 四、每个领取方的交付物

沿用 `collection-master-list.md` 第八节，落到 `docs/element-database/collections/` 下各自的子目录（建议 `a-rites/`、`b-races/`、`c-adventure/`）：

- 候选 JSON 与可读 Markdown。
- 参数表：含义、单位、范围、时间基准、事实/设计提案、来源、待核项。
- 关系表：起点 id、关系、终点 id、条件。未建条目标“待补”，不冒充已解析。
- 一份**规则候选样例**：输入状态、检定、四档结果、用到的 effect op、与现有契约的对应或冲突。
- 未解决问题清单。

状态一律保持 `needs_review` / `needs_detail`。原创玩法数值标“待平衡设计提案”。读到正文的来源才能标 `read`。

## 五、边界（必须遵守）

- **不改库、不改故事包、不改引擎、不启动服务**，不把素材采纳进任何世界。接线是后续任务。
- 不升级全库 schema，不重写旧文件，不合并或删除已有 id。
- 不搬运 D&D 专有名称、职业等级、CR、法术位、属性值。功能可以参考，名字和数值用织梦自己的。
- 不写现实危险操作：仪式步骤、护符制作、药物剂量、武器制造、开锁、制毒都不写可照做的流程。
- 信仰记述不等于超自然生效。超自然效果显式标为世界自选规则。
- 价格用 `docs/units.md` 的铜币与公制，不用旧便士体系。
- 0 表示真实的零，不表示“不知道”。未知单列。
- 同名先查重。已有 id 见本文第二节；引用优先于新建。

## 六、完成标准

- 三块都有候选文件和一份可阅读的样例，样例只使用现有 effect op 与六项属性。
- 每块都标出“现有契约能表达”和“需要新引擎能力”的分界，没有把未实现写成已实现。
- 没有改动 `app/`、`tests/`、`StoryPackage/`、百科数据库和已有元素 JSON。
- 审核状态没有被升格。
