日期：2026-11-11。**后续用户已确认：B世界构建与模拟、C数值玩法都要；四个方向全部补充，并可扩展更多内容；由其他智能体收集，本会话只提供列表。当前分派请用[全领域采集总清单](collection-master-list.md)。** 下文保留前轮优先级建议作参考，其中“先选一个方向”、Q1/Q2待确认及“按需才收数值”不再作为范围限制；事实、设计和适用条件仍须分开。本清单不宣称已逐条审计2247条内容。

## 1. 不必从零再收一遍的内容

已有：现实食材与材料工具、跨题材制度/力量/地点、种族与奇幻生物、魔药丹药、现实药材及方剂文献、多地菜系、职业店铺、政体科技、宗教神话诗歌、姓名、属性特质、建筑和人物/物品词条。

当前问题不是单纯“条目不够多”。建议从现有条目出发补**因果链、证据、适用条件与玩法数据**。建筑条目数量很大，不代表生活系统和生产链完整；是否重复、同义或仅是美术变体需要专项审查。

### P1：建议先补一条可演示的现实生活闭环

**建议试点：谷物→面粉→面包→店铺售卖→居民消费。** 已有小麦、工具、店铺、职业等模板可复用，优先补关系，不重新收集一套同名条目。

| 环节 | 必收定性数据 | 需要经济玩法时才收的量化数据 |
|---|---|---|
| 耕作/收获 | 气候土水、播收季、种子、劳力、工具、灾害 | 周期、面积、产量范围、用水与劳时条件 |
| 储存/运输 | 防潮虫鼠、容器、仓储、路线、装卸 | 重量容量、损耗、运时和费用 |

## 4. 待与用户确认的问题

下面是讨论项，不是已经生效的设计决定。

### Q1 设定资料库主要服务什么？
- A 叙事一致性：定义、变体、条件、冲突与来源为主。
- B 世界构建与模拟：在A基础上补生产、资源、组织、空间关系。
- C 全量数值玩法：进一步接战斗、配方、价格、时间和规则执行。
- **建议 B 分阶段推进，按玩法逐步做到 C**；所有资料条目都可有完整文字定义，但只给实际需要执行的模块加量化规则。

### Q2 首个补数据闭环选哪个？
- A 衣食住行/城镇生活（建议先选粮食与面包链）。
- B 冒险/怪物/装备。
- C 宗门/修行/魔法。
- D 国家/势力/历史。
- E 用户指定其他链。

### Q3 写实与原创如何共存？
- 沿用事实与设定分开、现实与奇幻均可采用。
- **建议**现实参考、类型母题、原创规则都允许，但关键断言明确性质；世界采用时声明覆写现实的部分。不要求原创寻找虚假历史依据。

### Q4 数值做到什么程度？
- A 先定性，不采产量/工时等。
- B 关键链采条件明确的区间与游戏基准（建议）。
- C 每类都完整量化。
- 价格、产量、工资、生态范围没有脱离规模/地区/时代的单一正确值；若选B/C，还需确认典型背景和时间粒度。

### Q5 候选能否用于创作？
- 当前实现允许作者显式确认待审候选后锁定，不等于审核升格。
- **建议**继续允许创作使用；关键现实断言先核验，原创机制由作者确认，最终导出清楚保留来源与审核状态。若改成“未审禁止采用”，属于行为变更，另行实施。

## 5. 下一步建议

用户先确认 Q1 和 Q2；据此从现有库挑一条样板链，列出已有ID与具体缺口，再制定该类的字段模板。讨论定稿后再安排采集/审核或实现迁移，不在本轮自动启动大批抓取、重建库或修改运行规则。
