# 元素资料采集交接

日期：2026-11-12。用途：项目负责人向其他智能体分派资料采集、结构整理和复核工作。本轮只提供交接文档；具体批次由负责人分配。

## 1. 领取任务时先确认四项

每个批次明确：专题编号、子范围、输出目录、交付阶段。专题编号沿用 [全领域采集总清单](collection-master-list.md) 的 01—60，不另建一套总分类。

交付阶段分为：

| 阶段 | 产物 | 完成标志 |
|---|---|---|
| 采集 | 可追溯的候选资料 | 定义、条件、来源、参数与关系齐全；未核处明确 |
| 整理 | 与现有格式兼容的候选文件 | 字段合法、ID 稳定、组内查重和引用检查完成 |
| 复核 | 断言与来源核对记录 | 每条受领断言都有支撑范围、结论和待办 |
| 导入 | 负责人单独指定的数据库写入 | 按既有导入器执行并报告实际差异；不自动采纳进故事 |

只领取采集任务时，交付停在候选文件。数据库导入、审核升格、公共索引和故事包变更需要在任务范围中另行写明。

## 2. 必读与按需阅读

领取任何专题时阅读：

1. [元素定义与内容规范](spec.md)：元素、变体、实例和规则候选的区别。
2. [全领域采集总清单](collection-master-list.md)：该专题及跨组专项的范围。
3. [单位与货币](../units.md)：新资料采用公制与整数铜币。
4. 负责人分配的现有同类样例，沿用其交换格式。

出现对应问题再阅读：

| 情形 | 参考 |
|---|---|
| 需要主标签、证据等级、科技或魔法档位 | [primary-tags-spec.md](../element-catalog/primary-tags-spec.md) |
| 跨题材原始候选 | [collection-spec.md](../element-catalog/collection-spec.md)；开局锁定的旧状态以当前元素规范和实现为准 |
| 需要了解现库结构或导入 | [database-使用说明.md](../human-encyclopedia/database-使用说明.md)、`app/encyclopedia.py` |
| 需要判断资料是否已变成规则 | [工程结构报告](../工程结构详细报告_2026-11-12.md)、对应规则契约 |
| 地图条件与字段 | [world-map-source-contract.md](../world-map-source-contract.md)、[map-backends.md](../map-backends.md) |
| 需要为游戏规划提供材料 | [综合游玩建议](../综合游玩建议_2026-11-12.md)；建议不等于已批准机制 |
| 需要区分公共资料、故事包背景与具体聚落 | [故事包定义与层级](../story-package-definition.md)；故事包采用世界设定，城镇生成在其下一级补充地方内容 |

地图现行默认为 `world_map_product`，civ-atlas 为可选后端。现有采集旧文档中“地图只用 civ-atlas”的文字已过时。采集时写地形、温度、水分、交通等条件；映射表注明来源、图层、单位、尺度和缺项，不把某个引擎的特定字段当通用条件。

## 3. 输出范围与文件

每个智能体只写负责人分配的目录，例如 `collections/<专题>/<批次>/`。具体目录由负责人给定，避免多个批次同名。复用现有候选 ID；跨组概念记录引用或待协调项。

一次交付建议包含以下五项，可按已有同类格式合并文件：

| 交付项 | 必备内容 |
|---|---|
| 候选 JSON | 项目现有交换格式的候选条目、来源和组身份；没有选定兼容格式时先交 Markdown，并列明待映射字段 |
| 可读说明 | 定义、典型用途、条件、限制、变体、例外和玩法用途 |
| 参数表 | 参数、单位、范围、规模/时间基准、证据性质、游戏适配与未定项 |
| 关系表 | 两端 ID、方向、关系、条件、数量或时间基准、外部待补节点 |
| 来源与问题清单 | 实际读取范围、支撑断言、冲突、重复候选、缺失数据和待负责人决策 |

批次说明记录实际完成的条目数与文件名。需要统一 schema 时提出差异，不由单个采集任务升级全库。

## 4. 收集什么才对游玩有用

每类资料至少能回答：它允许角色做什么、需要什么、改变什么、何时失效。具体世界状态留给故事和旅程实例。

| 类型 | 优先补充的信息 |
|---|---|
| 地点、地形与生态 | 进入/绕行条件、可见征兆、可调查信息、危险和季节限制 |
| 人物职业与组织 | 服务、准入、利益、义务、冲突、人物间的关系、信任建立和失信后果 |
| 工具、装备与材料 | 解决的行动问题、携带/使用成本、替代品、损耗与维修 |
| 衣装、标识与礼仪 | 在特定制度、地区和场合下的身份含义、行为规范、识别条件与可能的误认 |
| 生物与怪物 | 行为、需求、领地、沟通可能、识别线索、回避/安抚/驱逐方案 |
| 技能、法术与修行 | 目标、使用条件、成本、持续、反制、失效；战斗及非战斗用途分别说明 |
| 生产与经营 | 输入、设施、工时、产出、市场或服务对象、停工条件、委托管理需要 |
| 制度与信仰 | 适用地区、组织与群体、个体及不同种族的地位、权利义务、交往规范、争议与例外；制度要求、个人态度和实际行为分开，观念和客观超自然效力分开 |
| 事件和任务 | 冲突双方、信息差、介入方式、等待/拒绝的后果、后续变化 |

并非每个元素都要填写所有列。姓名不强填攻击力，制度不强填重量。缺少数据写缺少数据；原创参数标为设计候选。

领取社会关系、衣装或礼仪专题时，对照 [社会关系与第一印象](../综合游玩建议_2026-11-12.md#6-社会关系制度人物认知与第一印象) 记录适用条件与可能的行为含义；资料说明与剧情人物的具体判断分别记录。主观内心体验只为辅助注意与猜测提供条件资料，暂不扩写示例剧情或独立思想内容。

## 5. 参数和关系记录

参数表采用如下列义，文件格式沿用该批现有习惯：

```text
元素ID | 参数 | 含义 | 原始单位/数值 | 规模与时间基准
适用背景 | 来源/定位 | 事实或估算 | 游戏候选值 | 未确定事项
```

历史价格保留年代、地区、计价单位与原始记录。换算值和游戏铜币估值分别列出；既有游戏便士兼容规则不代表所有历史货币均可按 1:1 转铜币。存量、每批产量、单位时间流量使用不同参数。

关系表采用：

```text
起点ID | 关系 | 终点ID或待补概念 | 条件 | 数量/单位/时间 | 证据性质 | 备注
```

普通关联、材料依赖、社会关系和生态适用性分别说明；自然语言关系不是已执行的机器规则。跨组目标未核实存在时，保留名称及待解析说明。

## 6. 来源与复核

- 对需要公共事实依据的内容实际查阅资料，优先官方、原始规则、博物馆、研究机构与可定位的原始文献。
- 记录链接、标题、实际读取日期和具体支撑范围；只读到摘要或搜索结果时按实际访问级别记录。
- 现实机制、历史事实、信仰记述和原创游戏设计分别标注。来源存在不能替代断言核对。
- 参考 D&D、博德之门、极乐迪斯科或巫师时，注明对应作品/规则版本及借鉴概念；项目适配参数独立标为设计，不批量复制专有剧情、台词、人物和数据表。
- 候选继续保留既有待审状态。审核升格按现行权限逐项进行，不能用导入成功替代实质核验。

## 7. 可复制的分派文本

```text
任务：织梦元素资料采集

专题编号：<01—60>
子范围：<明确包括的概念、背景与排除项>
交付阶段：<采集 / 整理 / 复核；导入另行明确>
允许输出目录：<独立目录>
沿用格式与样例：<现有同类候选文件>
预期覆盖：<概念清单或覆盖范围；条数有要求时由负责人填>

先读 docs/element-database/agent-handoff.md，再按其中指针读取本专题所需规范。
交付候选、可读说明、参数、关系、来源和未解决问题。
复用已知稳定 ID；未核字段保留未知，设计估值与来源事实分开。
仅修改受领目录；公共清单、数据库、故事包、存档与运行配置保留原状。
完成时报告：文件、覆盖范围、实际条目数、已做检查、待协调项。
```

负责人填写具体范围后即可分派。已在其他批次领取的概念应先查重，再决定引用、变体或独立条目。

## 8. 接收交付时的检查

1. 文件落在受领目录，JSON 能解析，格式沿用指定样例。
2. 每个受领概念有定义、适用条件和限制；遗漏项列出原因。
3. 参数有单位、尺度和性质；游戏估值能与原始参考区分。
4. 组内 ID 无重复；跨组引用标明已存在或待解析。
5. 来源实际支撑对应断言；未核、冲突与原创部分能直接定位。
6. 说明当前完成的是采集、整理、复核还是导入；故事采纳与可执行规则另行记录。

资料达到这些条件即可进入负责人安排的下一阶段，不以凑齐大量条目代替内容完整性。
